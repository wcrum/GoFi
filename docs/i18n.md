# Internationalisation (UI)

The GoFi UI ships in **en-US** (source), **uk-UA** (Українська) and **zh-Hant**
(繁體中文（台灣）). Every user-visible string goes through `t()` / `<Trans>`
from `ui/src/i18n`; catalogs live in `ui/src/locales/<locale>/gofi.json` and are
generated from code. The runtime is `@grafana/i18n` (i18next underneath), the
same instance `@grafana/ui` uses for its own strings, so one language switch
covers both.

## Adding a string

```tsx
import { t, Trans, formatRelativeTime } from '../i18n'

<Button>{t('gofi.flows.toolbar.save', 'Save flow')}</Button>
<Field label={t('gofi.canvas.inspector.parse.from-label', 'Parse from')} />
t('gofi.flows.list.count', '{{count}} flows', { count, defaultValue_one: '{{count}} flow' })
<Trans i18nKey="gofi.shell.empty.hint" components={{ a: <a href="/docs" /> }}>
  Read the <a>flow guide</a> to get started.
</Trans>
<span>{formatRelativeTime(revision.createdAt)}</span>
```

- **Key**: `gofi.<area>.<component>.<slug>`, kebab-case slugs. Areas are the
  folders under `src` (`shell`, `pages`, `theme`, `canvas`, `python`, `cel`,
  `logs`, `lib`, `server`…). The key names the *place*, not the text, so the
  English can change without renaming the key.
- **Default**: the English text, written in code. It is the fallback when a
  locale lacks the key and the source `pnpm i18n:extract` writes to en-US.
- **Interpolation**: `{{name}}` with a `values` object. Never concatenate
  (`'Saved ' + name`) or split a sentence over several `t()` calls: word order
  differs per language. Keep punctuation inside the string (`'Last error:'`,
  not `'Last error' + ':'`).
- **Plurals**: pass `count`; i18next picks `_one`/`_few`/`_many`/`_other` per
  locale (Ukrainian has four forms, Chinese one). Give the English singular
  as `defaultValue_one`. The extractor generates the right forms per locale.
- **Rich text**: `<Trans>` with `components`; translators see `<a>…</a>` or
  `<0>…</0>` tags and keep them.
- **Numbers, dates, durations**: `formatNumber`, `formatDate`,
  `formatDateTime`, `formatTime`, `formatRelativeTime(iso | Date, now?)`,
  `formatDuration(ms)`. Never `toLocaleString()`, `toFixed()` for display or
  hand-built "5 minutes ago".
- **Not translated**: identifiers, flow names, YAML keys, code, log lines.
  Brand names and acronyms (GoFi, CEL, YAML, Kafka…) are fine as literals; they
  are in `ui/scripts/i18n-allowlist.json`. For anything else the lint flags
  on purpose, add `// i18n-ignore` on the line (or alone on the line above).
- `t()` results are plain strings and are **not reactive**; the app remounts
  on a language switch (see below), so computing labels at render time is
  enough. Do not call `t()` at module scope (compute inside a function).

## Scripts (run in `ui/`)

| Command | What it does |
| --- | --- |
| `pnpm i18n:extract` | i18next-parser (`i18next-parser.config.mjs`) scans `src/**/*.{ts,tsx}` for `t()`/`<Trans>`, rewrites `src/locales/en-US/gofi.json` with the English defaults, adds missing keys to uk-UA/zh-Hant as `""`, drops keys no longer in code, and resets a translation to `""` when its English default changed. Sorted, nested by `.`. Run it after adding strings and commit the result. |
| `pnpm i18n:check` | `scripts/i18n-check.mjs --allow-missing`: compares each locale with en-US; prints coverage, missing/empty keys, stale keys and placeholder problems. Exit 1 on stale keys or placeholders that do not exist in the source. |
| `pnpm i18n:check:strict` | Same without `--allow-missing`: untranslated keys fail too. Switch CI to this once translators keep up. |
| `pnpm i18n:lint` | `scripts/i18n-lint.mjs`: JSX text and `label/placeholder/title/tooltip/aria-label/description/text/message/confirmText/subTitle` props (and the same names in object literals) that contain letters and are not inside `t()`/`<Trans>`. Prints `file:line:col` and counts by area. Exit 0 unless `--strict` (CI) or `--max N`. |
| `pnpm verify` | `i18n:lint --strict`, `i18n:check` and `test` in one go; CI runs this (`npm --prefix ui run verify`), so a new hardcoded string fails the build. |
| `pnpm test` | includes `src/i18n/*.test.mjs` and `scripts/*.test.mjs` (resolution, plurals, detection, pseudo-locale, check/lint on fixtures). |

The lint parses with the TypeScript 5 compiler API that `i18next-parser` depends on
(the project's own `typescript` is the 7.x native compiler, which has no JS API).

## Locale files

```
ui/src/locales/
  en-US/gofi.json        generated: English defaults (source of truth for keys)
  uk-UA/gofi.json        translations; "" = untranslated (falls back to English)
  uk-UA/grafana-ui.json  optional: @grafana/ui component strings (see below)
  zh-Hant/gofi.json
  zh-Hant/grafana-ui.json
```

Nested by key segment: `gofi.shell.nav.flows` is `{"gofi":{"shell":{"nav":{"flows":"…"}}}}`.
en-US is bundled into the app; other locales are code-split and fetched when
selected (before first paint for a stored preference).

## Adding a locale

1. Add it to `LOCALES` in `ui/src/i18n/locales.ts` (tag, native name, English
   name, direction) and to the loaders in `ui/src/i18n/runtime.ts`.
2. Add the tag to `locales` in `ui/i18next-parser.config.mjs`, run
   `pnpm i18n:extract` (creates the folder with empty strings).
3. Detection: `matchLocale` compares the maximised language+script
   (`Intl.Locale.maximize()`), so `pt-BR` would match a `pt-BR` entry and
   `zh-HK` matches `zh-Hant`; add special cases only if that is wrong.
4. Translate, `pnpm i18n:check`, done. For an RTL locale set `dir: 'rtl'`;
   the runtime mirrors it to `<html dir>`.

## Switching language

- Stored in `localStorage['gofi.locale']`. Without a stored value the first
  `navigator.languages` entry that maps to a supported locale wins
  (`zh-TW`/`zh-Hant-TW`/`zh-HK` → zh-Hant, `uk` → uk-UA, `en-*` → en-US), else en-US.
- UI: the Appearance popover (palette button, top bar) has a **Language**
  section under Accent listing native names; and the Ctrl/⌘+K palette has
  actions "Language: Українська" etc. (search by English name or tag too).
- `useLocale()` returns `[locale, setLocale]`. `setLocale` persists, lazy-loads
  the bundle, calls i18next `changeLanguage`, sets `<html lang>`/`dir` and
  notifies subscribers. `I18nProvider` (in `main.tsx`, inside the router and
  theme providers) remounts the app tree with `key={locale}`, so every `t()`
  re-evaluates without a page reload; router location and theme survive, local
  component state (open drawers, unsaved form input) does not.
- `<html lang>` starts as `en` in `index.html` and is corrected before render.

## Grafana component strings

`@grafana/ui` 13.2.4 calls `t('grafana-ui.…', 'English')` for ~450 of its own
strings (Close, pagination, Select placeholders…) but **ships no translations in
the npm package** — Grafana keeps them in its own repo
(`public/locales/<locale>/grafana.json`, which has no uk-UA at all; zh-Hant
exists). `@grafana/i18n` also exports no catalogs. So by default those strings
stay English.

The runtime registers `grafana-ui` as a fallback namespace: anything in
`src/locales/<locale>/grafana-ui.json` (shape `{"grafana-ui": {...}}`, the
same as Grafana's file) is used for `grafana-ui.*` keys. Today those files hold a
handful of the most visible keys (close buttons, pagination, Select, spinner).
To cover more, copy the `grafana-ui` object from Grafana's `grafana.json` for the
matching Grafana version into that file. These files are not touched by
`i18n:extract`/`i18n:check`.

## Pseudo-locale (QA)

Open the UI with `?pseudo=1` (or set `localStorage['gofi.i18n.pseudo'] = '1'`
for a sticky toggle; `?pseudo=0` turns it off for a load). Every string that
goes through i18next — ours and Grafana's — renders as `[Šáṽé ƒĺóŵ ~~~]`:
bracketed, accented and ~35% longer. Plain English in the UI means a string
bypasses `t()`; a cut-off `]` means a layout that truncates. Placeholders and
`<Trans>` tags are preserved.

## Server errors

Connect errors from the Go controller are English today (`ConnectError.rawMessage`).
The UI-side hook is `translateServerError(code, params)` in
`ui/src/i18n/server-errors.ts`:

- `code` is a GoFi error code (`flow_not_found`) or a Connect status (`not_found`,
  `NotFound`, or the numeric code); `params.message` may carry the raw text.
- Resolution: GoFi code with params → known raw message → translated status
  label followed by the raw message, so nothing is hidden while messages are
  still English. A few of today's exact messages are mapped
  (`library credential required`, `function not registered`, …).

Plan for the Go side (not implemented yet): return `connect.NewError(code, err)`
with an error detail (a small `gofi.v1.ErrorInfo` message: `code string`,
`params map<string,string>`), keep the English `message` for logs and old
clients. The UI reads the detail, and `translateServerError(detail.code,
detail.params)` renders `gofi.server.error.<code>` with the params. Add the key
to `SERVER_CODES` when the server starts sending the code; `i18n:extract` picks
it up like any other string.

## zh-Hant glossary

Traditional Chinese as used in Taiwan (台灣用語): 軟體, 伺服器, 資料, 設定, 網路,
檔案, 預設, 資訊, 記憶體, 連線, 日誌 (for logs; 記錄 as the verb "recorded"), 快取.
Register: concise technical UI, like Grafana's zh-Hant interface. Full-width
punctuation（，。：；（）「」）in Chinese sentences; half-width inside code-like
fragments (`host:port`, `gofi-<flow name>`). A space between Chinese and Latin
words or digits (`{{count}} 個資料流`, `Python 函式庫`), none around full-width
punctuation. Product, protocol and resource names stay English (GoFi, Kafka,
CEL, YAML, JSON, TCP/UDP, Zenoh, S3, SQL, Pod, Service, Gateway, NodePort, UDS
Package, Broker). Plurals: zh-Hant has only `_other`; counts read
`{{count}} 個資料流`. Palette/search keyword strings keep the English terms and
append Chinese ones so both match.

Typography: Ukrainian quotes «…», apostrophe ’ (U+2019), en dash for ranges
(1–65535), non-breaking thin punctuation not required. Plurals carry
`{{count}}`/`{{n}}` in every form (`_one` covers 21, 31 …), except where the
English `_one` form has no placeholder (the check script rejects one there).

QUIC, TLS, Zenoh, S3, SQL, Pepr, UDS) and code (`fields`, `meta`, `raw`,
decorators) stay untranslated.
